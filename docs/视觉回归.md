# 视觉 A/B 回归基线

> 本文档面向**行为敏感变更**（像素处理、alpha、尺寸、配置或 CLI 行为）的开发者。
> 对应 GitHub issue [#1](https://github.com/asinkLuno/img2pixelart/issues/1)。

## 目的

流水线参数众多（perceive / structure / render / ascii 共 25 项，完整清单见参数总表）。任何改动算法默认值
或内部量的 PR，都必须先跑 A/B 基线，确认 **B 相对 A 无可感知的质量回退** 后再动手。
本页是这套栅极（gate）的固定入口。

## 一条命令复现

```bash
# 当前实现（A 侧）的完整像素画 + ASCII 矩阵
uv run python tools/visual_regression.py baseline
```

固定基准集：

| 图片 | 说明 |
| --- | --- |
| `tests/cup.png` | 带 alpha 的方形测试图 |
| `tests/cup_no_padding.png` | 裁边后的 cup |
| `docs/assets/banana_orig.png` | 照片型原图 |
| `docs/assets/chair_orig.png` | 照片型原图（无 alpha） |

- 像素画：`width=height ∈ {48, 64, 96}`；
- ASCII：`rows ∈ {40, 60}`；
- 输出：`outputs/ab/baseline/<UTC timestamp>/`（已被 `.gitignore` 忽略，不入库）。

## A/B 实验

| # | A | B |
|---|---|---|
| `ab-2` | 现状（bilateral → mean-shift） | 跳过 bilateral，直接 mean-shift |
| `ab-3` | 固定 `canny_low=40 canny_high=120` | ratio×Otsu 自适应（同 ASCII 方案） |

```bash
uv run python tools/visual_regression.py ab-2
uv run python tools/visual_regression.py ab-3
```

AB-1（`dither_method=bayer` vs `pattern/ordered`）已在 issue #1 中得出结论并据此
合并（bayer 等价于 ordered，见 #3），runner 不再包含该实验。

每个命令在 `outputs/ab/<experiment>/<UTC timestamp>/` 生成：

- 每个（图片 × 尺寸）组合的 A / B `result.png` 与调试中间产物（`05_palette.png`、
  `22_palette_strip.png` 等）；
- `comparison.png`：A | B 逐行拼接的评审大图；
- `metrics.json`：逐像素差异比例、平均通道差异、palette / strip 是否一致。

## 判定方式

1. 打开 `comparison.png` 人工评审，**以人工结论为准**；
1. 参考 `metrics.json`：差异比例显著、palette 不一致（含形状变化，说明色相族数量
   变了）意味着结构级变化，需要更强理由；
1. 结论以 `AB-N: 结论 / 倾向 / 证据（输出路径或贴图）` 格式写成 issue 评论；
1. P1 / P2 工作开始前必须引用对应 AB 结论。

## 实验补丁机制（AB-2 / AB-3）

实验的变体侧（非现状一侧，例如 ab-2 的 B、ab-3 的 A）实现写在
`tools/visual_regression.py` 的 `_apply_patch` 中，运行前复制包到临时
目录再打补丁，**不修改开发工作树**。补丁使用精确字符串匹配，若 `perceive.py` 实现
移动会显式报错——避免悄悄比较了错误的算法。新增实验只需在 `EXPERIMENTS` 表里加一项
并实现对应 patch。

## 可复用性

- 行为敏感 PR 的验收：先 `baseline`，再针对受影响配置跑对应 `ab-N`，贴出结论；
- 新增基准图片：`git add -f` 纳入版本控制后在 `PIXEL_SOURCES` 中登记；
- 需要并行加速时可按 `tools/visual_regression.py` 的命令构造
  `hydra/launcher=joblib` 变体（默认逐条顺序执行，保证输出可定位）。
